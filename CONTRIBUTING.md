# Contributing to The Kitchen Codex

Thank you for your interest in contributing to The Kitchen Codex! Contributions, ideas, bug reports, and feature requests are welcome.

The Kitchen Codex is an Obsidian-based recipe management project designed to make it easier to organize, discover, and work with recipes stored in an Obsidian vault.

## Ways to Contribute

There are several ways you can help improve The Kitchen Codex:

* Report bugs
* Suggest new features
* Improve existing functionality
* Improve documentation
* Improve the user interface or user experience
* Submit code changes
* Share ideas for better recipe organization and management

## Before You Start

Before opening an issue or submitting a pull request:

1. Check existing issues to see if the problem or suggestion has already been reported.
2. Review the README for project information and setup instructions.
3. For larger changes, consider opening an issue first so the proposed change can be discussed.

## Reporting Bugs

When reporting a bug, please provide as much useful information as possible.

Include:

* A clear description of the problem
* Steps to reproduce the issue
* What you expected to happen
* What actually happened
* Your Obsidian version
* Your operating system
* Screenshots or error messages when helpful

Please remove any personal or private information before posting screenshots, logs, or other files.

## Suggesting Features

Feature requests are welcome.

Please explain:

* What you would like to see added
* Why the feature would be useful
* How you think it could work
* Any examples or use cases that would help explain the idea

## Pull Requests

Pull requests should focus on one change or related group of changes.

Before submitting a pull request:

* Make sure your changes are focused and understandable.
* Test your changes before submitting.
* Update documentation when appropriate.
* Make sure existing functionality has not been unnecessarily broken.
* Keep commits reasonably clear and descriptive.
* Reference an existing issue when applicable.

Please provide a clear description of what your pull request changes and why.

## Code Style

Follow the existing coding style and structure of the project.

Avoid making unrelated changes in the same pull request. Small, focused changes are easier to review, test, and maintain.

## Documentation

Documentation improvements are always welcome.

If you add or change functionality, consider whether the README or other documentation should be updated as well.

## Questions

If you're unsure about something, feel free to open an issue and start a discussion before making a large change.

## Code of Conduct

All contributors are expected to follow the project's [Code of Conduct](CODE_OF_CONDUCT.md).

Thank you for helping make The Kitchen Codex better!
